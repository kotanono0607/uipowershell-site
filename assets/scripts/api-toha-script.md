# 台本：APIってなに？（用語シリーズ#4・深掘り版）

- 位置づけ：1動画＝1概念の深掘り。M2の「つなぐ（連携）」を担う技術＝APIを丁寧に解く。
- 題材軸：システムAの値を、システムBに手で打ち直す（＝二重入力の温床）
- 1メッセージ：**API＝アプリ同士の"受付窓口"。決まった形で頼むと決まった形で返る。人を介した打ち直しを、直接の受け渡しに変える**
- 狙い：初心者に用語(API)を教える
- 尺：約2:10〜2:30（目安・6シーン）／ナレーター：VOICEVOX ずんだもん（speaker 3）
- POV／持論：**「同じデータの手移し（コピペ往復）は、つなげば消える」**
- 深さ担保：定義（A/P/I分解）＋仕組み（レストランの例え）＋限界（相手が公開していないと使えない）を必ず入れる。

---

## S1｜痛み（hero画像＋図解 api-01）
- テロップ：その数字、システムを「またいで」手入力していませんか？
- ナレーション：システムAの画面で数字を確認して、それを、システムBに、また手で打ち込む。見て、写して、また見て、写して。コピペの往復。その合間に、写し間違いも、まぎれ込む。

## S2｜用語の登場（api-02）
- テロップ：今日は「つなぐ」の技術
- ナレーション：このシステム同士の"受け渡し"を、人を介さずに、直接やってくれる仕組みがあります。名前は、API。

## S3｜定義＝頭文字の分解（中心図解 api-03）
- テロップ：API＝アプリ同士の「受付窓口」
- ナレーション：APIは、英語の頭文字。エーは、アプリケーション、アプリ。ピーは、プログラミング、プログラム用の。アイは、インターフェース、受付窓口。つまり、アプリ同士が、決まった形でやり取りするための、窓口のことです。人間用の画面ではなく、プログラム用の入り口、というのがポイント。

## S4｜仕組み＝レストランの例え（api-04）
- テロップ：注文の「お決まりの形」で頼む
- ナレーション：イメージは、レストラン。あなた、つまりシステムAが、ウェイター、つまりAPIに、メニューの決まった形で注文する。ウェイターが厨房、つまりシステムBに伝え、料理、つまりデータが返ってくる。厨房の中身を知らなくても、決まった頼み方さえ守れば、ちゃんと受け取れる。

## S5｜限界＝相手が窓口を開けていないと（api-05）
- テロップ：APIは「両側の対応」が要る
- ナレーション：ただし、ここが大事。APIは、相手のシステムが、窓口を公開していないと、使えません。仕様が変わることもあるし、回数の制限や、認証が要ることも。つなぐには、両側の対応が必要。どこへでも通じる、魔法の配線ではない、ということです。

## S6｜行動喚起（締め api-06）
- テロップ：まず「2回打っている所」を探す
- ナレーション：まずは、同じデータを、2つのシステムに手入力している場所を、ひとつ探してみる。そこが、API連携の、いちばんの候補です。つながれば、打ち直しごと、まるごと消えます。
